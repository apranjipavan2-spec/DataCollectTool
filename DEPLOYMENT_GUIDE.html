Complete Deployment & Operations Guide

⚡ Quick Start (5 minutes)

For Users (Enumerators)

  1. Access the app: Open browser → http://app.fieldpulse.local (or production URL)
  2. Login: Enter phone number + password
  3. Collect data: Open assigned form → answer questions → submit (works offline)
  4. Auto-sync: When online, data syncs automatically in background

For Supervisors

  1. Login: Use supervisor credentials
  2. Dashboard: View real-time submission counts, assign forms to enumerators
  3. Review: Click submissions to see details, flag for clarification
  4. Export: Download CSV or Stata files for analysis

For Admins

  1. Build forms: Click "Builder" → add fields, skip logic, sections
  2. Manage team: Add users, assign roles (enumerator, supervisor, admin)
  3. Configure: Set white-label branding, plan tier, usage limits
  4. Monitor: Check server stats, database usage, error logs
✓ That's it! The app handles offline storage, compression, and background sync automatically.

🖥️ Local Development Setup

Prerequisites

  • Docker & Docker Compose (for PostgreSQL + Redis)
  • Node.js 18+ (for frontend)
  • Python 3.11+ (for backend)
  • Git

Step 1: Clone Repository

cd C:\Life\DataCollectTool

Step 2: Start Databases (Docker)

docker compose up -d

This starts:

  • PostgreSQL on localhost:5432
  • Redis on localhost:6379

Step 3: Backend Setup

cd backend pip install -r requirements.txt python -m alembic upgrade head python scripts/seed_dev.py

This creates:

  • Database schema (migrations)
  • Test users (admin, supervisor, enumerator)

Step 4: Start Backend Server

python -m uvicorn app.main:app --port 8000

Open http://localhost:8000/docs to see interactive API documentation

Step 5: Frontend Setup

cd ../frontend npm install npm run dev

Opens http://localhost:5173 (with hot reload enabled)

Test the Setup

  • Frontend loads at http://localhost:5173
  • Backend API docs at http://localhost:8000/docs
  • Can login with test credentials
  • Can submit a form (saved locally)
  • Can view dashboard
✓ Development setup complete!

📱 Offline Data Collection Guide

How Offline Collection Works

FieldPulse is designed to work without internet:
  1. Data stored locally on device (phone storage)
  2. Auto-saves every 300ms as you type
  3. No internet required for data collection
  4. Syncs automatically when connected
  5. Works on 2G/3G/4G/WiFi

Step-by-Step: Collecting Data Offline

1. Before Going Offline

Download forms to your device

Simply open the app while online. Forms are automatically cached locally.

When you go offline, you'll still see all your assigned forms in the "Collect" tab.

2. Collecting While Offline

Fill forms normally (no internet needed)
1. Tap form name 2. Answer questions (one at a time) 3. Take photos/video (auto-saved locally) 4. Record audio (auto-saved locally) 5. Tap "Submit" when done

3. After Submission (Still Offline)

Data is saved on your phone

Data stored in phone's local storage (OPFS or IndexedDB)

Safe even if phone crashes or loses power

Forms can be re-opened to edit before syncing

4. When You Come Online

Automatic sync (no action needed)

Detection: When your phone reconnects to internet, FieldPulse automatically:

  1. Syncs all pending submissions (text data)
  2. Uploads all photos/audio files
  3. Marks submissions as "synced"
  4. Supervisor can see them on dashboard

Network Speeds & Data

Connection Text Sync Time Per Photo Per Audio
2G (Edge) 2-3 seconds 8-12 seconds 5-8 seconds
3G 1-2 seconds 4-6 seconds 2-4 seconds
4G/LTE <1 second 1-2 seconds <1 second
WiFi <1 second <1 second <1 second
Note: Photos are automatically compressed from ~5MB to ~200KB, reducing upload time and data usage by 96%!

Storage on Phone

  • Text data: ~1KB per submission
  • Photos: ~200KB each (after compression)
  • Audio: ~100KB per 30 seconds
  • Total for 500 submissions: ~50MB (very small)
✓ Phone storage is rarely an issue — even with 500+ submissions, you only need 50-100MB

⚙️ Daily Operations & Monitoring

Morning Checklist

  • Check server health: GET /health
  • Verify database backups completed
  • Check error logs for overnight issues
  • Confirm Google Drive has space for media
  • Review submission sync status

Monitoring Commands

Check backend logs
docker logs datacollecttool-backend-1 --tail 100 -f
Check database health
psql postgresql://user:pass@localhost/fieldpulse -c "SELECT count(*) FROM submissions;"
Check Redis cache
redis-cli PING redis-cli INFO memory

Common Issues & Solutions

Issue: Backend not responding

Solution: Restart backend container

docker restart datacollecttool-backend-1

Issue: Submissions stuck in sync

Solution: Check network connectivity, server logs, and database connections

docker logs datacollecttool-backend-1 | grep -i sync

Issue: Database running out of space

Solution: Archive old submissions, increase disk size, or upgrade server

Backup & Recovery

Daily backup
# Run daily via cron job pg_dump postgresql://user:pass@localhost/fieldpulse > /backups/fieldpulse-$(date +%Y-%m-%d).sql # Upload to S3 aws s3 cp /backups/fieldpulse-*.sql s3://my-bucket/backups/
Restore from backup
psql postgresql://user:pass@localhost/fieldpulse < /backups/fieldpulse-2026-03-25.sql

🔗 API Reference

Base URL

http://localhost:8000/api/v1

Authentication

1. Login (get JWT token)
POST /auth/login Content-Type: application/json { "phone": "+919999990001", "password": "test@123" } Response: { "access_token": "eyJ0eXAi...", "token_type": "bearer", "user": { "id": "uuid", "phone": "+919999990001", "role": "master_admin" } }
2. Use token in requests
GET /forms/ Authorization: Bearer eyJ0eXAi...
3. Or use API Key (for programmatic access)
POST /api-keys/ → generates API key Authorization: Bearer your-api-key-here

Main Endpoints

Method Endpoint Purpose Auth
POST /auth/login Login with phone + password None
GET /forms/ List forms (filtered by role) JWT
POST /submissions/ Create submission JWT
POST /sync/push Push pending submissions JWT
POST /sync/media Upload photo/audio JWT
GET /export/submissions/{form_id}/csv Export submissions as CSV JWT
POST /api-keys/ Generate API key JWT
